# Tuffex 统一组件使用政策

> geek_bot 的管理后台全部用 Tuffex 0.6.0，不另建平行的通用 UI 体系。

状态：`current` · 更新：2026-09-25 · 适用：`app/console` 与一切界面改动

## 范围

geek_bot 的管理后台（`app/console`）全部用 Tuffex 0.6.0（Vue 3.5）。页面必须用库里已有的同类组件，不另建平行的通用 UI 体系，不重复实现库里已经提供的基础组件。这是所有者的硬性要求；选型记录为 ADR-0009（#2 写入），依赖和外壳由 #4 引入。

本文只写 Tuffex 专属的引入、封装和版本规则。界面的硬性规则只在 [DESIGN](../../design/DESIGN.md)「硬性规则」一节定义，技术选型见 [STACK](../../design/STACK.md)，本文不另写一份；安全、模块边界、贡献等其他规范见 [docs 总入口](../../README.md)。

## 引入、封装与主题

按 [安装说明](reference/installation.md) 使用组件子路径及对应 CSS，应用外壳统一引入基础令牌样式。根入口和全量样式只在有书面记录的情况下使用。

不能用自己写的同名组件冒充 Tuffex。项目适配层只处理主题令牌、少量共用组合和应用行为，不把所有 Props 重新包一层，也不隐藏类型。业务组合留在所属页面模块；共享组件不反向依赖业务页面。

组件库确实没有覆盖的需求，先记录检索结果，再评估用已有组件组合。需要新的基础原语或别的 UI 库时，说明缺口和维护成本，并取得所有者的明确批准，不编造 Tx 组件。

换肤的规则见 [DESIGN](../../design/DESIGN.md)「视觉」；Tuffex 有哪些令牌和组件变量，查上游的 [主题](reference/theming.md)。

## 版本治理

运行版本以 `app/console/package.json` 与 `pnpm-lock.yaml` 为准，版本钉死。上游快照的 manifest 声明 Node >=26、Vue ^3.5.27，与本仓库的 Node 22 基线不同；#4 接入时实测并记录结论。文档固定的源码提交不等于已经核实 npm latest；接入和升级都要同步更新匹配的参考资料。普通开发和检查不自动更新上游文档。升级 Tuffex 版本单独立项。新增页面的验收必须基于真实使用的组件和工具链。
